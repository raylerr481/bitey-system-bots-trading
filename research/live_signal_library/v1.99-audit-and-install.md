# Bitey SBT v1.99 — telemetry bridge and evidence audit

## What was added
- `research/Bitey_SBT_v1_99_Telemetry_Bridge.mq4`: standalone, non-trading EA. It emits a structured closed-bar observation once per chart bar.
- `research/mt4/BiteySBTStructuredTelemetry.mqh`: JSON escaping, HTTP POST, event identifiers, explicit broker-time field without a false UTC suffix, and useful error logging.
- This is a research candidate. It does not modify production EA files, submit orders, close trades, change risk settings, or collect account numbers.

## Important scope limitation
MT4 does not expose a supported MQL4 API to subscribe to the entire Experts tab or intercept `Print()` calls from other EAs. This bridge transmits only events it creates itself. To send a specific SBT EA's decisions, replace that EA's relevant `Print(...)` call with a structured call to `SBT99_LogEvent(...)`, or implement a separate external log-file collector. Do not claim complete Experts-tab capture from this bridge.

## Install on the desktop MT4
1. In MT4 choose **File > Open Data Folder**.
2. Copy `Bitey_SBT_v1_99_Telemetry_Bridge.mq4` into `MQL4/Experts/`.
3. Copy `BiteySBTStructuredTelemetry.mqh` into `MQL4/Experts/mt4/` (create the `mt4` folder).
4. Open the EA in MetaEditor and compile. Resolve any compiler messages before attaching it.
5. In **Tools > Options > Expert Advisors**, enable **Allow WebRequest for listed URL** and add:
   `https://bitey-system-bots-trading.raylerr481.workers.dev`
6. Attach the bridge to a chart. It has no trade-order calls and cannot place trades.
7. Inspect the Experts tab for `SBT99 TELEMETRY` status. HTTP 2xx means the upstream responded successfully; it does not alone prove durable storage. Verify the event is present in the backend's research store.

## Backend prerequisite
The Worker route forwards `POST /api/v1/mt4/signal-event` to the configured SBT API base. The upstream must implement that route, authenticate the dedicated `X-MT4-Token`, validate the schema, deduplicate `event_id`, and persist events to a research-only store. Keep GitHub tokens and database service keys on the server, never in MT4. The receiver and durable storage have not been validated by this change.

## Strategy profitability: do not overclaim
The v1.98.4 assembly candidate uses close-to-close historical proxies, not broker-executed SL/TP simulations. Before describing a variant as better, run:
- chronological train / validation / untouched holdout splits;
- conservative intrabar ordering when SL and TP occur in the same candle;
- variable spread, commissions, swap, slippage and gaps;
- per-symbol contract/tick-value validation and lot-step/minimum-lot constraints;
- out-of-sample expectancy in R, profit factor, max drawdown, trade count and confidence interval;
- forward demo tests on the intended broker feed.

The 16 models (trend, momentum, Donchian, mean reversion, strict range, ATR breakout, session bias, RSI divergence, higher-timeframe trend, Bollinger expansion, MACD, linear regression, volatility squeeze, Fibonacci pullback, break/retest and VWAP-deviation proxy) should be compared by net holdout expectancy and regime, not training win rate alone. Similar models must not be counted as independent votes without correlation/group checks. A rolling typical-price-volume average is a VWAP proxy, not necessarily the broker's true session VWAP.

## Test limitation
MetaQuotes documents that `WebRequest()` does not execute in Strategy Tester. Test trading/risk logic in Strategy Tester separately, then test HTTP telemetry on a running terminal chart. No MetaEditor compilation or end-to-end HTTP persistence is asserted by this commit.


## Send the MT4 Experts log from the desktop
1. In MT4 select **File > Open Data Folder** and copy the full folder path.
2. In PowerShell, run the script from a trusted local copy:
   `$env:SBT_MT4_TOKEN = "your dedicated ingestion token"` (only if the backend requires one; do not use a GitHub PAT).
3. Run:
   `./research/mt4/Send-MT4-Experts-To-Bitey.ps1 -TerminalDataPath "C:\path\to\your\MT4\data"`
4. It tails new lines in the latest `MQL4/Logs/*.log` file, redacts common credential/account fields, and posts each line to `/api/v1/mt4/signal-event`. Failed posts are queued in `SBT_Experts_pending.jsonl` inside the terminal data folder and retried periodically. Stop with Ctrl+C.

This reads the terminal's log file underlying the Experts tab, not the visible UI itself. It begins at the end of the current log and does not upload old history by default. Backend route, authentication and durable storage must be verified before treating the upload as complete. The collector does not modify the EA or place orders.
